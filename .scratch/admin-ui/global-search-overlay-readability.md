## Agent Brief

**Category:** bug
**Summary:** The GlobalSearch dialog overlay uses `bg-black/80` (80% black opacity) which is too aggressive for a quick-search palette, making the command palette content hard to read.

**Current behavior:**
The GlobalSearch dialog renders a full-screen overlay with `bg-black/80` (80% black opacity). This makes the search input and results appear on an overly dark background, reducing readability. The command palette content (`bg-popover` background) lacks sufficient contrast against the strong overlay.

**Desired behavior:**
The GlobalSearch dialog overlay should use `bg-black/30` (30% black opacity) instead of `bg-black/80`. This provides sufficient visual separation from the page content while keeping the command palette text clearly readable. The overlay change should apply to the GlobalSearch component specifically (not the project-wide DialogOverlay), so other dialogs retain their existing 80% opacity.

**Key interfaces:**
- The `GlobalSearch` component — wraps a `<Dialog>` with `<DialogContent>`
- The `DialogOverlay` in `admin-ui/src/components/ui/dialog.tsx` — currently hardcoded to `bg-black/80`
- Fix approach: either pass a custom `className` to the GlobalSearch dialog's overlay, or create a wrapper that overrides the overlay style

**Acceptance criteria:**
- [ ] The GlobalSearch dialog overlay uses `bg-black/30` (or equivalent reduced opacity) instead of `bg-black/80`
- [ ] All other dialogs in the app still use `bg-black/80` (no global regression)
- [ ] The search input text and results list are clearly readable
- [ ] The overlay transition (fade-in/fade-out) remains smooth
- [ ] No build errors or lint warnings (`npm run lint` in `admin-ui/`)

**Out of scope:**
- Changing the overlay opacity for all dialogs globally
- The nested-dialog overlay stacking bug in `BlueprintFormModal` (separate issue: `nested-dialog-overlay-stacking.md`)
- Search results not appearing due to backend bugs (separate issues)
