## Agent Brief

**Category:** bug
**Summary:** Navigation Drawer links cannot be clicked on desktop because the main content area stacks above the drawer in the z-axis.

**Current behavior:**
On desktop viewport (≥768px), clicking navigation links in the drawer fails because the `<main>` element's `<div class="p-4">` content div intercepts pointer events. Playwright reports the main subtree intercepts clicks over the drawer's `<aside>` element. The drawer uses `md:static` positioning (no z-index), while `<main>` appears later in the DOM and naturally stacks on top.

**Desired behavior:**
All navigation links in the drawer should be clickable on all viewport sizes. The drawer should either use `position: relative; z-index` to stack above main content, or the main content should have appropriate margin/padding when the drawer is open.

**Key interfaces:**
- The `AppShell` component's layout — renders `<NavigationDrawer />` then `<main>` in a flex container
- The `NavigationDrawer` component's `aside` element — uses `md:static md:z-auto` which removes the z-index on desktop

**Current behavior:**
When the Navigation Drawer is open on a desktop viewport (≥768px), clicking any navigation link inside the drawer fails because the `<main>` element's content div intercepts pointer events. Playwright reports:
```
<div class="p-4">…</div> from <main class="flex-1 min-w-0 transition-[margin] duration-300">…</main> subtree intercepts pointer events
```

**Desired behavior:**
Navigation links in the drawer should be clickable on all viewport sizes. The drawer should have proper z-index/layering when open, or the main content should have a `margin-left` offset when the drawer is open to prevent overlap.

**Key interfaces:**
- `admin-ui/src/components/AppShell.tsx` — Layout: `<NavigationDrawer />` then `<main>` in the flex container
- `admin-ui/src/components/NavigationDrawer.tsx` — The drawer `<aside>` with `md:static md:z-auto` classes on desktop

**Acceptance criteria:**
- [ ] Navigation Drawer links are clickable on desktop (≥768px) when drawer is open
- [ ] Main content does not intercept pointer events when drawer is open
- [ ] The fix works at all viewport sizes (mobile, tablet, desktop)
- [ ] No regressions in drawer open/close animations or responsive behavior

**Root cause analysis:**
On desktop (`md:` breakpoint), the drawer `<aside>` uses `md:static md:top-auto md:left-auto md:bottom-auto md:z-auto`. This takes it out of fixed positioning and places it in normal flow. The `<main>` element (which includes a `<div class="p-4">` wrapper around `<Outlet />`) is positioned later in the DOM. Since both are static elements in the same flex container, the `<main>` naturally stacks above the drawer in the z-axis (later DOM elements are rendered on top). The drawer's `z-40` class only applies below the `md:` breakpoint (mobile), where it's also `fixed` positioned.

**Out of scope:**
- Mobile drawer overlay behavior (this uses fixed positioning + z-40 which works correctly)
- Drawer close/open animation timing
- The drawer close state (`w-0 md:overflow-hidden`)
