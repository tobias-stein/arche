## Agent Brief

**Category:** bug
**Summary:** `BlueprintFormModal` renders 5 separate `<Dialog>` components side-by-side. When a sub-dialog (e.g., `GlobalAttributePickerDialog`) opens on top of the main dialog, two `bg-black/80` overlays stack to ~96% opacity, making content nearly unreadable.

**Current behavior:**
The `BlueprintFormModal` component renders its main create/edit `<Dialog>` and 4 sub-dialogs (`ConfirmDialog`×2, `GlobalAttributePickerDialog`, `AffixPickerDialog`×2) as siblings in a React fragment. Each is a full `@radix-ui/react-dialog` with its own portal-based `<DialogOverlay>` using `bg-black/80` (80% black opacity). When a sub-dialog is opened while the main dialog is still visible, both overlays appear simultaneously. Because both are semi-transparent, they accumulate to ~96% effective opacity, dimming the picker content so severely that text becomes very hard to read.

**Desired behavior:**
When a sub-dialog opens within the BlueprintFormModal, only one overlay should be visible at a time. The content of the active dialog should be clearly readable against its background. Approaches include:
- Hiding the main dialog's overlay while a sub-dialog is open (the main form stays visible but loses its darkened backdrop)
- Replacing the sub-dialogs with non-overlay components (e.g., popovers or drawers)
- Using a single shared overlay at the app level

**Key interfaces:**
- `BlueprintFormModal` component in the admin-ui source that renders the main dialog and all sub-dialogs
- The Radix UI `DialogOverlay` styling in `admin-ui/src/components/ui/dialog.tsx` (`bg-black/80`)
- Each of the sub-dialog components: `GlobalAttributePickerDialog`, `AffixPickerDialog`, `ConfirmDialog`

**Acceptance criteria:**
- [ ] Opening the `GlobalAttributePickerDialog` while the main BlueprintFormModal is open shows only one overlay (or no overlay stacking)
- [ ] Opening an `AffixPickerDialog` while the main modal is open shows only one overlay
- [ ] Opening a `ConfirmDialog` while the main modal is open shows only one overlay
- [ ] All dialog content (text, buttons, form fields) is clearly readable when active
- [ ] The change does not break focus trapping or dismissal (Escape, click-outside) for any dialog
- [ ] Existing tests pass (`npm test` in `admin-ui/`)

**Out of scope:**
- The GlobalSearch dialog overlay (separate issue: `global-search-overlay-readability.md`)
- Other pages with multiple dialog instances that are opened sequentially (these work correctly)
- Changing the overlay opacity value project-wide
