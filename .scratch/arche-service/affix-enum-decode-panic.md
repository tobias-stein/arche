## Agent Brief

**Category:** bug
**Summary:** Affix row parsing panics because `row.get("type")` expects `String` but the PostgreSQL column uses the custom enum `affix_location`.

**Current behavior:**
When there are affixes in the database, any request that reads from the `affixes` table (e.g., `GET /api/affixes`, `GET /api/affixes/{id}`) causes a panic at the row-deserialisation step because `row.get("type")` fails with a column-type mismatch (`TEXT` ≠ `affix_location` enum). The server returns an empty response to the client and logs a panic trace. The cache background-reload task also crashes when it encounters affix rows.

**Desired behavior:**
The `type` column on the `affixes` table should be readable without panicking. The value should be deserialised into a `String` or, preferably, into a Rust enum that maps to the PostgreSQL `affix_location` type. All endpoints that read affixes should return data normally.

**Key interfaces:**
- The row-deserialisation logic (currently `affix_row_to_affix` / `row_to_affix`-style helpers) that reads the `type` column from the `affixes` table
- The `Affix` type — its `location` field currently maps from a `String` parsed from the DB; this should work naturally with an enum or a cast-to-text approach
- Any cache-reload code that reads the `affixes` table

**Acceptance criteria:**
- [ ] `GET /api/affixes` returns affix data (not a panic / empty response) when affix rows exist
- [ ] `GET /api/affixes/{id}` returns a single affix when the row exists
- [ ] `GET /api/affixes` returns an empty list (not a panic) when no affixes exist
- [ ] The cache background-poller does not panic when it encounters affix rows during a reload
- [ ] Existing tests continue to pass (`cargo test -p arche-service`)

**Out of scope:**
- The same class of bug on the `global_meta_attributes` table (`value_type` column) — handled in a separate issue (`gma-enum-decode-panic.md`)
- The same class of bug in the cache poller — handled in a separate issue (`cache-poller-enum-panic.md`)
- Schema migrations or changes to the PostgreSQL enum types
- Affix CRUD behaviour unrelated to reading from the database
