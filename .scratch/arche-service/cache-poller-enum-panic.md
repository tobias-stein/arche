## Agent Brief

**Category:** bug
**Summary:** The background cache poller panics when reloading data from tables that use PostgreSQL custom enum types (`affix_location`, `value_type`).

**Current behavior:**
The cache poller runs on a timer and queries the `affixes` and `global_meta_attributes` tables when it detects changes. The queries use `row.get("type")` and `row.get("value_type")` to deserialise columns that are PostgreSQL custom enum types. These calls panic with a column-type mismatch (`TEXT` ≠ `affix_location` / `value_type` enum). The panic kills the poller task, so the cache never picks up changes. Subsequent requests to the affected endpoints may also fail because the same row-deserialisation code is used.

**Desired behavior:**
The cache poller should successfully reload data from all tables without panicking, regardless of whether the table uses custom enum columns. The deserialisation should handle `affix_location` and `value_type` enum columns gracefully (cast to `TEXT` in SQL, or use proper sqlx enum mappings). The cache should stay up-to-date after any write operation.

**Key interfaces:**
- The cache reload logic in the service's cache module that queries the `affixes` and `global_meta_attributes` tables
- The row-deserialisation functions shared with the request handlers (the same `row.get()` calls that also panic in the handler path)

**Acceptance criteria:**
- [ ] After creating an affix via `POST /api/affixes`, the cache poller reloads without panicking
- [ ] After creating a GMA via `POST /api/global-meta-attributes`, the cache poller reloads without panicking
- [ ] The cache reflects the new data within one poll cycle
- [ ] No panic traces appear in server logs during normal operation with mixed data
- [ ] Existing tests continue to pass (`cargo test -p arche-service`)

**Out of scope:**
- The same class of bug in the request-handler path — handled in separate issues (`affix-enum-decode-panic.md`, `gma-enum-decode-panic.md`)
- Cache performance tuning or poll-interval changes
- Adding new cacheable entities
