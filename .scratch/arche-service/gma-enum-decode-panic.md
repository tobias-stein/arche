## Agent Brief

**Category:** bug
**Summary:** GMA row parsing panics because `row.get("value_type")` expects `String` but the PostgreSQL column uses the custom enum `value_type`.

**Current behavior:**
When there are global meta attributes in the database, any request that reads from the `global_meta_attributes` table (e.g., `GET /api/global-meta-attributes`, `GET /api/global-meta-attributes/{id}`) causes a panic at the row-deserialisation step because `row.get("value_type")` fails with a column-type mismatch (`TEXT` ≠ `value_type` enum). The server returns an empty response to the client and logs a panic trace. The cache background-reload task also crashes when it encounters GMA rows.

**Desired behavior:**
The `value_type` column on the `global_meta_attributes` table should be readable without panicking. The value should be deserialised into a `String` or, preferably, into a Rust enum that maps to the PostgreSQL `value_type` type. All endpoints that read GMA rows should return data normally.

**Key interfaces:**
- The row-deserialisation logic that reads the `value_type` column from the `global_meta_attributes` table
- The `GlobalMetaAttribute` type — its `value_type` field should deserialise correctly from the DB column
- Any cache-reload code that reads the `global_meta_attributes` table

**Acceptance criteria:**
- [ ] `GET /api/global-meta-attributes` returns GMA data (not a panic / empty response) when rows exist
- [ ] `GET /api/global-meta-attributes/{id}` returns a single GMA when the row exists
- [ ] `GET /api/global-meta-attributes` returns an empty list (not a panic) when no rows exist
- [ ] The cache background-poller does not panic when it encounters GMA rows during a reload
- [ ] Existing tests continue to pass (`cargo test -p arche-service`)

**Out of scope:**
- The same class of bug on the `affixes` table (`type` column) — handled in a separate issue (`affix-enum-decode-panic.md`)
- The same class of bug in the cache poller — handled in a separate issue (`cache-poller-enum-panic.md`)
- Schema migrations or changes to the PostgreSQL enum types
- GMA CRUD behaviour unrelated to reading from the database
