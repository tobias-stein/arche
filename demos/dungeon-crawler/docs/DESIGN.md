# Dungeon Crawler Demo — Design Document

## Overview

A 2D pixel-art top-down rogue-like dungeon explorer (Diablo 2 aesthetic, Zelda dungeon structure) with turn-based combat (Final Fantasy style) where all game content (creatures, items, spells) is defined and generated by the **Arche** procedural generation service.

The game is an ephemeral single-session SPA: no save/load, no persistence. Close the browser and you start over.

## Architecture

```
docker-compose.yml
├── postgres:16          ← Arche's database
├── arche-service        ← Rust API server (generate endpoint + CRUD)
└── dungeon-crawler      ← Vite dev server, serves the game SPA
```

The game is a **client-side SPA** (no game backend). It calls `POST /api/generate` directly from the browser. Arche has `CorsLayer::permissive()` so cross-origin requests are allowed.

The API key is embedded for local dev (fine in a Docker Compose demo).

### Shared Stat Reference Curve

All stats derive from a single linear reference curve, ensuring consistent power scaling:

```
referenceAttack(level)  = 5 + (level - 1) * 0.5
referenceDefense(level) = 2 + (level - 1) * 0.3
referenceHealth(level)  = 20 + (level - 1) * 2.0
```

Archetype-specific multipliers determine final stats (see blueprint attribute tables above). ±10% variance is added for natural feel.

### Generation Flow

**Creature spawn** (per spawn slot):
```
1. Game computes level window: playerLevel ± creatureLevelVariance (clamped to 1-100)
2. Game constructs Arche request with level + difficulty constraints:
   // Non-boss rooms:
   { "constraints": { "level": { "gte": 3, "lte": 7 },
                      "difficulty": { "in": ["normal", "champion", "elite"] } } }
   // Boss rooms:
   { "constraints": { "level": { "gte": 85, "lte": 100 },
                      "difficulty": { "in": ["boss"] } }, "count": 1 }
3. Arche picks a blueprint via weighted random — blueprint weights determine
   which difficulty is drawn. No game-side difficulty pre-roll needed.
4. Game reads the `difficulty` from the response for aggro range / visuals.
```

**Loot drop** (per drop slot after victory or chest open):
```
1. Game computes level window: creatureLevel ± itemLevelVariance (clamped to 1-100)
2. Game constructs Arche request with level constraint only:
   { "constraints": { "level": { "gte": 3, "lte": 7 } } }
   — No archetype filter, no rarity filter. Arche picks from all matching
     blueprints (items, spells, potions) via weighted random selection.
3. Game reads the `rarity` from the response for visual styling.
```

**Key principle:** Rarity/difficulty emerges naturally from Arche's blueprint
weights, not from game-side pre-rolls. The seed script calibrates weights so that
common/normal blueprints are selected ~2× more often than uncommon/champion,
~3× more than rare/elite, and ~5× more than boss/legendary ones.

## Game Mechanics

### Dungeon

- **Layout:** Zelda-style room-by-room. Each room fills the screen (or scrolls for larger rooms).
- **Doors:** N/S/E/W exits. Walk through a door → screen transitions to next room.
- **Transitions:** Phaser scene fade/slide to adjacent room.
- **Creatures:** Spawned when entering a room. Visible, patrol/wander. Avoidable by walking around.
- **Respawn:** Leaving and re-entering a room respawns new creatures.
- **Safe rooms:** Some rooms have no creatures.
- **Obstacles:** Walls, pits, breakable jars. Jars may contain consumables.
- **Chests:** Contain random loot (weapon, armor, accessory, spell, potion).
- **Boss room:** One final room with a boss creature. Beating the boss = game win.
- **Floor count:** 1 floor only (no stairs).

### Dungeon Generation Algorithm

- **Grid**: rooms placed on an N×N grid (e.g. 8×8 = 64 cells, ~30–50 rooms selected)
- **Connectivity**: Randomized Prim's spanning tree ensures all rooms reachable
- **Loops**: 15–25% extra edges added for branches and shortcuts (so the dungeon isn't a straight line)
- **Boss placement**: The room with greatest graph distance from entrance becomes the boss room
- **Guarantee**: All rooms are reachable from entrance (spanning tree property)

### Combat

- **Trigger:** Player sprite touches creature sprite → world freezes → combat UI appears.
- **Format:** Turn-based, 1-vs-1 (player vs one creature).
- **Turn order:** Player always goes first.
- **Player actions (menu-driven):**
  - **Attack** — deals `weapon_damage - creature_defense` (min 1)
  - **Cast Spell** — opens spellbook, choose a spell
  - **Use Item** — opens inventory, consume a potion
  - **Flee** — escape combat (chance-based)
- **Enemy turn:** AI chooses attack (simple: attack if HP > threshold, special if not).
- **Damage formula:** `damage = max(1, attacker_attack - defender_defense)`
- **Loot drop:** After victory, loot popup shows dropped item(s). Player can take or leave items in the popup before it auto-closes.

### Player Stats

| Stat | Source | Base value |
|---|---|---|
| health | weapon/armor/accessory bonuses + base | 100 |
| mana | accessory bonuses + base | 30 |
| attack | weapon damage stat | 10 (0 if naked, +weapon damage) |
| defense | armor/shield/accessory bonuses | 5 (0 if naked, +gear defense) |

All progression is **gear-based**. No XP-based stat growth for stats themselves — level only controls generation window.

Player starts with a Rusty Sword equipped (+3 damage), 2 Health Potions, and 1 Mana Potion in inventory.

### Post-Victory Recovery

After defeating a creature, the player recovers 15% of max HP and 15% of max mana. This sustains the player through multiple consecutive fights without forcing constant potion chugging.

### Combat Damage Formula

- Player attack: `max(1, player_attack - creature_defense + rand(0-2))`
- Creature attack: `max(1, creature_attack - player_defense + rand(0-2) - 2)`

### Player Level

Despite no stat growth, player **levels up** from kills. Level determines the generation window for items and creatures:
- `generation_level_band = player_level ± variance` (variance default 2, clamped to 1-100)
- Selection within the band is uniform — Arche's weighted random determines which blueprint is chosen
- Player starts at level 1. Reaches level 100 in ~1 hour playtime.
- Leveling pace: early levels fast (every 1-2 kills), later levels slower (5-10 kills).

### Inventory

- 18 slots, 1 item per slot (no stacking).
- Items can be equipped from inventory, or dropped on the ground (`[X]` key).
- `[Enter]` on an **item** in inventory equips it. `[Enter]` on a **potion** consumes it immediately (heals HP/mana).
- `[S]` on a **spell** item in inventory adds it to the spellbook.
- Equipped items are removed from inventory (freeing their slot). Each equipment slot holds exactly one item — swapping unequips the old one back to inventory.
- **Auto-equip:** When picking up gear (loot drop or chest) and the matching equipment slot is empty, the item is equipped directly instead of going to inventory. Only goes to inventory if the slot is already occupied.
- **Item comparison:** When hovering/selecting an item in the inventory, the UI shows the slot name, the selected item's stats, and the currently equipped item's stats (or "empty") directly below the item row.

### Spellbook

- Limited to 6 slots.
- Spells are found as drops (loot or chests).
- **Spells bypass inventory** — picking up a spell adds it directly to the first empty spellbook slot. If the spellbook is full, the player must erase a spell (`[Del]` in spellbook view) to free a slot before picking up a new one.
- Spells can also be stored as items in the inventory. `[S]` on a spell item in inventory adds it to the spellbook.
- In combat, choose "Cast Spell" → opens spellbook → select a spell.

### Equipment Level Requirement

Each blueprint has a fixed `level` attribute (single int). The generated item's level must be ≤ player level for the player to equip it. Items above player level are greyed out.

## Data Population (Seed Script)

See `docs/adr/0006-fixed-level-blueprint-model.md` for the design rationale. See `scripts/seed.ts` for the implementation.

The seed script populates Arche's database via HTTP API. It generates ~500 blueprints with fixed integer levels and stats from the shared reference curve.

### Creature Distribution (Target — achieved via blueprint weights)

| Difficulty | Target frequency | Weight guide | Prefixes | Suffixes | Affix tier |
|---|---|---|---|---|---|
| normal | ~50% | 1.0 | 0 | 0 | n/a |
| champion | ~25% | 0.5–0.7 | 1 | 0 | by creature level |
| elite | ~15% | 0.3–0.4 | 1 | 1 | by creature level |
| boss | ~10% | 0.1–0.2 | 2 | 1 | by creature level |

These are seed script guidelines. The actual distribution emerges from Arche's
weighted random selection. No game-side logic replicates these weights.

### Item Distribution (Target — achieved via blueprint weights)

Same weight approach as creature difficulty.

| Rarity | Target frequency | Weight guide | Prefixes | Suffixes | Affix tier |
|---|---|---|---|---|---|
| common | ~50% | 1.0 | 0 | 0 | n/a |
| uncommon | ~25% | 0.5–0.7 | 1 | 0 | by item level |
| rare | ~15% | 0.3–0.4 | 1 | 1 | by item level |
| legendary | ~10% | 0.1–0.2 | 2 | 1 | by item level |

### Level Distribution

Each blueprint has a fixed integer level (1-100). At generation time, the game computes a flat band `playerLevel ± variance` (default ±2, clamped to 1-100) and Arche selects from matching blueprints via weighted random. No band mapping or range rolling needed.

## Testing

- **Unit tests** (Vitest) for core game logic: combat math, inventory, equipment, spell casting, leveling.
- **Integration tests**: seed script output validates against Arche import schema.
- **Full-stack smoke test**: Docker Compose up → Arche healthy → game can generate a thing.

  - Player can move through rooms

  - Combat actions (attack, cast spell, use item, flee) produce correct outcomes

## UI Design

See `UI.md` for the complete UI specification. Key decisions from the design session (2026-05-30):

- **Responsive**: mobile, tablet, and desktop layouts. All inputs (touch, mouse, keyboard) supported for every action. All icons use FontAwesome 6 — no emoji characters anywhere in the UI. No hover-only interactions. Touch targets ≥44×44px.

- **Player card**: top-left always. HP/MP bars + ATK/DEF/Lv/XP.
- **Enemy card**: bottom-right during combat only.
- **Action menu**: center-screen 2×2 grid (Attack / Cast Spell / Use Item / Flee).
- **Unified log**: bottom-left collapsible panel. Timestamps + FontAwesome icons.
- **Mini-map**: full-screen `[M]` toggle. Grid spanning tree (20–50 rooms), fog-of-war, breadcrumb trail.
- **Inventory**: right slide panel, 18 slots. Floating tooltip with equip comparison.
- **Spellbook**: right slide panel (same area), 7 slots. Replacement dialog when full.
- **Encounter**: dimmed card with creature info + Engage/Flee.
- **Combat**: fade to dedicated scene with dark background. Action grid + enemy card.
- **Loot**: vertical list popup, inventory + spellbook accessible simultaneously.
- **Controls**: `[H]`/`[?]` full-screen overlay. Mouse/touch supported everywhere.
