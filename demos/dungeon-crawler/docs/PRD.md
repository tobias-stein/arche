## 1. Product Overview

### Elevator Pitch

A 2D top-down rogue-like dungeon explorer (Diablo 2 aesthetic, Zelda dungeon structure) with turn-based combat (Final Fantasy style). All game content (creatures, items, spells) is defined and generated by the **Arche** procedural generation service. The game is an ephemeral single-session SPA — no save, no load, no persistence. Close the browser and you start over.

### Architecture

```
docker-compose.yml
├── postgres:16          ← Arche's database
├── arche-service        ← Rust API server (generate endpoint + CRUD)
└── dungeon-crawler      ← Vite dev server, serves the game SPA
```

- **Client-side SPA** — no game backend. Calls `POST /api/generate` directly from the browser.
- **Arche** has `CorsLayer::permissive()` for cross-origin requests in local dev.
- API key is embedded for local dev (fine in Docker Compose demo).

### Tech Stack

| Layer | Choice | Reason |
|---|---|---|
| Game framework | **Phaser.js** (3.x) | Battle-tested 2D, tilemaps, scene management, camera, programmatic Graphics API |
| UI shell | **React** (18+) | Familiar, wraps Phaser canvas, handles modals/overlays (inventory, loot, combat UI) |
| State management | **Plain TypeScript GameState class** (EventEmitter) | Single source of truth; Phaser reads sync per frame, React subscribes reactively |
| Rendering | **Phaser WebGL** | Pixel-art style, smooth scrolling, mobile-friendly |
| Canvas style | **Phaser tilemap (Tiled format)** | Grid-based rooms, programmatic tile drawing |
| Game logic | **TypeScript** | Type safety, shared types with seed script |
| Seed script | **TypeScript** | Generates Arche import JSON (blueprints, affixes, global meta attributes) |
| Docker | **Docker Compose** | Spins up postgres + arche-service + game |
| Typography | **Pixel Game** font family | Regular + Extrude styles; replaces Courier New |

### Phaser + React Integration

Phaser is embedded inside React (created in a `useEffect`, rendered into a `<div>` ref). React DOM overlays sit above the canvas via CSS absolute positioning. Both read from the same `GameState` class. Phaser renders the dungeon tilemap, player movement, creature sprites, room transitions, and combat fade. React renders all HUD elements: player card, enemy card, action menus, unified inventory/equipment/spellbook dialog, unified log, mini-map, loot dialog, encounter prompt, and help overlay.

### GameState Architecture

A plain TypeScript class extending EventEmitter:

- **Single source of truth** for all game state (player stats, inventory, combat, dungeon map, visited rooms)
- **Synchronous reads**: Phaser render loop reads `.player.hp`, `.player.position` etc. directly every frame with zero overhead
- **Reactive subscriptions**: React components subscribe via `useEffect` + `useState` — the GameState emits events (`playerHpChanged`, `inventoryChanged`, `combatStarted`, `roomChanged`) and React re-renders
- **GameActions** layer: functions like `playerCombatAttack()`, `movePlayer(dir)`, `takeLootItem(id)` that mutate GameState and emit events
- **Testable**: all game logic can be unit-tested without Phaser or React

Data flow: `Input → GameActions → GameState → (Phaser render | React re-render)`

## 2. Game Design

### Core Loop

1. Player enters dungeon → room loads with creatures, chests, doors
2. Player explores room, avoids or triggers creatures
3. Creature encounter → turn-based combat (1v1)
4. Victory → loot popup + XP gain → post-victory recovery (15% HP/MP)
5. Continue exploring → find boss room → defeat boss → game win

### Dungeon

- **Layout:** Zelda-style room-by-room. Each room fills the screen (centered tilemap with vignette).
- **Grid:** Rooms placed on an N×N grid (default 64×64, ~2250 rooms at 55% occupancy).
- **Connectivity:** Randomized Prim's spanning tree ensures all rooms reachable.
- **Loops:** ~20% extra edges added for branches and shortcuts.
- **Boss placement:** Room with greatest graph distance from entrance.
- **Doors:** N/S/E/W exits. Walk through a door → fade-to-black transition to adjacent room.
- **Transition effect:** 350ms CSS opacity fade (black overlay). Player appears at corresponding entry tile in adjacent room.
- **Respawn:** Leaving and re-entering a room respawns new creatures and chests.
- **Floor count:** 1 floor only (no stairs).

### Room Layout

- Each room is a **15×11 tile grid**.
- Outer ring = walls, interior = checkerboard floor.
- Doors at N/S/E/W midpoints (only if adjacent room is connected).
- No obstacles, pits, breakable jars — bare rooms with walls, floor, and doors only. All gameplay comes from creatures, chests, and containers.

### Dungeon Generation Algorithm

See `room-generator-minimap.md` for full algorithm reference. Summary:

1. **Prim's growth:** Start from a random seed cell. Maintain a frontier of adjacent empty cells. Randomly pick one to add as a room. Target occupancy ~55% of grid cells.
2. **Spanning tree:** Each room records its parent during growth, forming an implicit spanning tree.
3. **Adjacency:** Built via spatial `Map` keyed by `"x,y"` (O(n), not O(n²)).
4. **Extra edges:** ~20% of non-tree adjacencies randomly added for loops/shortcuts.
5. **Boss room:** BFS from entrance over connection set → max distance room.
6. **Connection set:** Tree edges + extra edges determines which adjacent rooms have doors.

### Creature Behavior

| Aspect | Specification |
|---|---|
| **Spawn count per room** | 1–4 random. Boss room: exactly 1 boss creature. No safe rooms — all rooms have spawns. |
| **Spawn positions** | Random floor tiles, minimum **4 tiles** from the entry door tile (prevents auto-aggro on room entry). Soft constraint: try to avoid overlapping aggro ranges. |
| **Movement** | Stationary at spawn position until aggro'd. No patrol/wander. |
| **Aggro range** (tile radius, Chebyshev distance) | Normal: 1 tile. Champion: 2 tiles. Elite: 3 tiles. Boss: 3 tiles. |
| **Chase behavior** | Creature moves toward player at **half player speed** (every 2nd player step). Only the **nearest** aggro'd creature chases the player at any time — others remain stationary at their spawn. |
| **Encounter trigger** | Player walkable tile overlaps creature tile (same-tile collision). |
| **Combat format** | 1-vs-1, turn-based. Only the touched creature engages. |
| **Post-encounter (flee)** | Creature stays at the encounter position. Gains a **1.5s stun window** (no aggro, no movement) to allow player to escape aggro range. After stun, creature resumes stationary behavior at its current position. |
| **Post-combat (defeat)** | Creature is removed from the room. |
| **Post-combat (victory)** | Creature is removed. Loot popup appears. Post-victory recovery: 15% max HP, 15% max MP restored. |

### Combat

- **Trigger:** Player sprite touches creature sprite → world freezes → encounter prompt (dimmed card with creature info + Engage/Flee).
- **Engage:** Fade into dedicated combat scene (dark background, no dungeon visible).
- **Combat scene:** Player card (top-left), enemy card (bottom-right), action menu (center, 2×2 grid).
- **Turn order:** Player always goes first.
- **Player actions (menu-driven):**
  - **Attack** — `max(1, player_attack - creature_defense + rand(0-2))`
  - **Cast Spell** — opens small overlay spell list panel (not the full inventory dialog). Each spell shows name, mana cost, damage/heal. Insufficient mana = greyed out.
  - **Use Item** — opens small overlay consumables panel (not the full inventory dialog). Shows potions in inventory.
  - **Flee** — confirmation dialog with "Yes, Flee" / "Stay & Fight".
- **Enemy turn:** AI chooses attack: `max(1, creature_attack - player_defense + rand(0-2) - 2)`
- **Victory:** Brief flash → loot popup (centered card) over dimmed dungeon. Post-victory recovery applied.
- **Defeat:** Screen dims to red → Game Over overlay with stats.

#### Combat Action Panels

Cast Spell and Use Item open **small overlay panels** (centered, compact list), NOT the full inventory dialog. This is a deliberate design choice — combat actions need quick selection without navigation overhead.

**Spell selection panel:** Header ("Select Spell"), close button, scrollable list of spells. Each entry: icon, name, mana cost (right-aligned). Disabled styling for spells the player lacks mana for. Max-height list with scrollbar.

**Use Item panel:** Same layout. Header ("Use Item"), close button, scrollable list of consumables. Each entry: icon, name, effect value (right-aligned). Empty state: "No usable items."

**Flee panel:** Confirmation card. Header ("Flee from combat?"), sub-text ("Cowardice has its rewards."), two buttons: "Yes, Flee" (red/danger) and "Stay & Fight" (green/confirm).

### Player Stats

| Stat | Source | Base value |
|---|---|---|
| health | weapon/armor/accessory bonuses + base | 100 |
| mana | accessory bonuses + base | 30 |
| attack | weapon damage stat | 10 (0 if naked, +weapon damage) |
| defense | armor/shield/accessory bonuses | 5 (0 if naked, +gear defense) |

All progression is **gear-based**. No XP-based stat growth. Level controls the generation window only.

### Player Level

- Player starts at level 1. Reaches level 100 in ~1 hour playtime.
- Leveling pace: early levels fast (every 1–2 kills), later levels slower (5–10 kills).
- Generation window: `player_level ± variance` (variance default 2, clamped to 1-100). Uniform selection within the band — Arche's weighted random determines which blueprint is chosen.

### Post-Victory Recovery

After defeating a creature, the player recovers **15% of max HP** and **15% of max mana**. This sustains the player through multiple consecutive fights without forcing constant potion chugging.

### Inventory

- **18 slots**, 1 item per slot (no stacking).
- Items can be equipped from inventory, or dropped (`[X]` key with abandon confirmation dialog).
- `[Enter]` on an **item** equips it. `[Enter]` on a **potion** consumes it immediately.
- `[S]` on a **spell** item in inventory adds it to the spellbook.
- Equipped items are removed from inventory (freeing their slot). Each equipment slot holds exactly one item — swapping unequips the old one back to inventory.
- **Auto-equip:** When picking up gear and the matching equipment slot is empty, the item is equipped directly instead of going to inventory.
- **Drag and drop:** Items can be dragged between inventory slots, from inventory to equipment slots (matching slot type), and from the DROP zone (trash can) to discard. Drag creates a floating clone of the item. Valid drop targets are highlighted in green, invalid in red. Dropping on an occupied valid slot swaps the items. Dropping on the DROP zone opens an "Abandon [item]?" confirmation dialog.

#### Item Comparison (Floating Tooltip)

When hovering/selecting an item in inventory, a floating tooltip shows the slot name, selected item's stats, and the currently equipped item's stats (or "empty"). Desktop: hover to show, click to pin. Tablet: tap to select → auto-dismiss after 3s. Mobile: inline comparison below the slot (no floating tooltip).

### Loot Drops

| Difficulty | Drop count | Rarity distribution (Common / Uncommon / Rare / Legendary) |
|---|---|---|
| Normal | 0–1 items | 80% / 20% / — / — |
| Champion | 1–3 items | 30% / 50% / 20% / — |
| Elite | 3–5 items | — / 20% / 50% / 30% |
| Boss | 5–7 items | — / — / 30% / 70% |

- **Item level:** `player_level ± 2` (normal distribution).
- **Item type distribution:** Handled by Arche's weight system on blueprints. Each blueprint has a `weight` — higher weight = more likely to be selected.
- **Spells drop as items:** Picked up → goes to inventory → player presses `[S]` to add to spellbook.
- **Chests:** Contain random loot using the same generation flow as creature drops.

### Spellbook

- **7 slots**.
- Spells are found as drops (loot or chests) and picked up as items into inventory.
- `[S]` on a spell item in inventory adds it to the first empty spellbook slot.
- If spellbook is full: replacement dialog appears showing current spells + new spell. Player selects a slot to replace. Confirmation: "Replace [old spell] with [new spell]?"
- `[Del]` / `[Backspace]` on a spell in the spellbook erases it (with confirmation).

### Loot Popup

Centered card after victory / chest opening:

- "VICTORY!" title with XP gain and level-up notification
- Vertical list of dropped items (icon + name + type/rarity badge)
- Actions: `[↑/↓]` navigate, `[Enter]` take selected (auto-equips or goes to inventory/spellbook), `[Space]` take all, `[Esc]` leave all, `[I]` open inventory dialog
- Inventory and spellbook remain accessible while loot popup is open (player can manage space)

The loot popup also supports **drag-and-drop** — items can be dragged from the loot grid into inventory slots or equipment slots directly, with the auto-equip float animation for empty slots.

### Chests

- Present in rooms alongside creatures.
- Opening a chest triggers the same loot popup as creature victory.
- Chests respawn when re-entering a room.

### Encounter Prompt

Centered card on dimmed dungeon background. Shows creature name (with difficulty badge), brief stats (HP, ATK, DEF). Options: `[Enter]` Engage (fade to combat scene), `[Esc]` Back away (player steps back one tile, creature remains at its position).

### Game Over Screen

Full-screen overlay when player HP reaches 0. Large "GAME OVER" text. Stats: level reached, rooms explored, enemies slain, time survived. `[Enter]` or "Play Again" button → restart. `[Q]` or "Quit" → title screen.

### Victory Screen

Full-screen overlay when boss is slain. Large "YOU WIN!" text. Stats: final level, rooms explored, enemies slain, items collected. `[Enter]` or "Play Again" → restart. `[Q]` or "Quit" → title screen.

### Title Screen

Full-screen on initial load. Game title (large, centered), subtitle/tagline, "Press Enter to Start" or tap-to-play. Background: static dungeon-themed pattern or animated graphic.

### Controls Overlay

Full-screen overlay. Toggle with `[H]` or `[?]` key, or clickable help button. Dismiss with any key or tap. Lists all keyboard/mouse/touch bindings in two-column grid layout (Movement, Combat, Inventory, Map, General, Loot).

### Shared Stat Reference Curve

All creature, item, spell, and potion stats derive from a single linear reference curve, ensuring consistent power scaling across all content. A level-N creature and a level-N weapon are always in the same power band.

**Reference formulas:**

```
referenceAttack(level)  = 5 + (level - 1) * 0.5   → range: 5 (L1) to 54.5 (L100)
referenceDefense(level) = 2 + (level - 1) * 0.3   → range: 2 (L1) to 31.7 (L100)
referenceHealth(level)  = 20 + (level - 1) * 2.0  → range: 20 (L1) to 218 (L100)
```

**Archetype multipliers:**

| Archetype | Attack | Defense | Health | Notes |
|-----------|--------|---------|--------|-------|
| Creature (normal) | 1.0x | 1.0x | 1.0x | Baseline |
| Creature (champion) | 1.2x | 1.2x | 1.5x | |
| Creature (elite) | 1.5x | 1.5x | 2.0x | |
| Creature (boss) | 2.0x | 2.0x | 4.0x | |
| Weapon | 0.8x | — | — | Damage stat |
| Armor | — | 0.7x | — | Defense bonus |
| Shield | — | 0.5x | — | Defense bonus |
| Accessory | 0.3x | 0.3x | — | Flex bonus |
| Potion | — | — | 2.0x | Heal amount |
| Spell (damage) | 1.2x | — | — | |
| Spell (heal) | — | — | 1.5x | |

**Example at level 10:**
- Reference: ATK=9.5, DEF=4.7, HP=38
- Normal creature: ATK=10, DEF=5, HP=38
- Champion creature: ATK=11, DEF=6, HP=57
- Level 10 weapon damage: ~8
- Level 10 armor defense_bonus: ~3

The seed script applies these multipliers when generating blueprints. ±10% variance is added for natural feel.

### Affixes

Affixes are tiered by level (4 tiers: Weak 1–30, Strong 20–60, Greater 50–85, Mythic 75–100). Each affix is generated 4 times with different names and scaled ranges. See DESIGN.md for full affix table. Affix tier is determined by the generated entity's level. Rarity/difficulty determines how many affixes are rolled from that tier.

Spells receive affixes based on rarity: uncommon = 1 prefix (element), rare = 1 prefix + 1 suffix (power bonus), legendary = 2 prefixes + 1 suffix. No common spells — affixes only start at uncommon.

### Generation Flow

**Creature spawn** (per spawn slot in a room):
1. Game computes level window: `playerLevel ± creatureLevelVariance` (clamped to 1-100)
2. Game constructs Arche request with level constraint:
   - Non-boss rooms: `{ level: { gte: X, lte: Y }, difficulty: { in: ["normal", "champion", "elite"] } }`
   - Boss rooms: `{ level: { gte: X, lte: Y }, difficulty: { in: ["boss"] } }`
   - No rarity/difficulty weights are passed — Arche's blueprint weights determine which difficulty is drawn
3. Arche filters blueprints by the level band using gte/lte on Single values, then picks one via weighted random
4. Game reads the `difficulty` from the response and applies it (aggro range, visual style, etc.)

**Loot drop** (per drop slot after creature victory or chest open):
1. Game computes level window: `creatureLevel ± itemLevelVariance` (clamped to 1-100)
2. Game constructs Arche request with level constraint only — no archetype, no rarity filter:
   `{ constraints: { level: { gte: X, lte: Y } } }`
3. Arche picks from all blueprints (items, spells, potions) matching the level window via weighted random
4. Game reads the response's `rarity` attribute and applies visual styling (rarity triangle, name color, etc.)

**Key design principle:** Rarity/difficulty and item type emerge naturally from Arche's blueprint weight system, not from game-side pre-rolls. The seed script calibrates blueprint weights so that common/normal blueprints are selected roughly ~2× more often than uncommon/champion, ~3× more often than rare/elite, and ~5× more often than boss/legendary ones. This keeps all drop-rate tuning in the seed script (and ultimately in Arche's data), not scattered across game config and source code.

### Seed Script

A TypeScript seed script (`scripts/seed.ts`) populates Arche's database directly via HTTP API. Run before first game launch: `docker compose run --rm seed`.

The script generates ~500 blueprints with fixed integer levels. All stats are computed from the shared reference curve with archetype-specific multipliers. See "Shared Stat Reference Curve" section above.

## 6. Asset Specification

### Rendering Technique

All entities are drawn **programmatically** using **Phaser Graphics API** (`Phaser.GameObjects.Graphics`). No pixel-art sprite sheets, no image assets, no external art. The Canvas 2D drawing calls from the prototypes are converted to their Phaser equivalents.

### Tilemap Rendering

Each room is a grid with the following tile types:

| Type | Rendering |
|---|---|
| Wall | Dark green/grey fill with lighter top/left edge highlights, darker bottom/right shadows. Brick line decoration at alternating rows. Shadow line every 3rd column. |
| Floor | Checkerboard pattern (two alternating green tones). Subtle grid lines. |
| Door (N/S/E/W) | Archway shape — dark void background with an arched cutout in the wall. Directional arch shape (arched top for N/S, arched side for E/W). Pulsing golden glow effect (sine wave intensity). |

**Vignette:** A radial gradient overlay (center transparent → edges `rgba(0,0,0,0.45)`) applied over the entire room for atmosphere.

### Player Entity

**Shape:** Filled circle with radial gradient.

| Part | Rendering |
|---|---|
| Body | Radial gradient circle (`#e8dfd0` → `#d0c8b8`), margin 16% of tile size |
| Outline | 1px stroke `#b0a898` |
| Size | Fits within tile with 16% margin |

*Prototype reference: `room-layout-and-assets.html`, `drawPlayer()`*

### Chest Entity

**Shape:** Rounded rectangle with gold gradient.

| Part | Rendering |
|---|---|
| Body | Rounded rect, linear gradient (`#8b7355` lightened 30 → `#8b7355`), margin 16% |
| Outline | 1px stroke darkened 40 |
| Symbol | "?" symbol in `#f0e8d8` centered, font size 34% of tile |

*Prototype reference: `room-layout-and-assets.html`, `drawChest()`*

### Enemy Entities

**Shape:** Triangle (point-up) with difficulty-based color.

| Part | Rendering |
|---|---|
| Body | Triangle, linear gradient (color lightened 50 → color), margin 20%, 57.7% half-width |
| Outline | 2px stroke (base color), 1px stroke (darkened 40) |
| Symbol | "!" symbol in `#f0e8d8` centered, font size 30% of tile |
| Colors | Normal `#889096`, Champion `#d4883a`, Elite `#c83838`, Boss `#7a388a` |

*Prototype reference: `room-layout-and-assets.html`, `drawEnemy()`*

### Item Icons in Slots

Items in inventory/equipment/loot grids are rendered as FontAwesome icons + text name. Each slot:
- Icon: FA icon matching item type (18px in grid)

## 8. Technical Specification

### Code Organization (High-Level)

The codebase is organized into four broad areas. Agents working on implementation decide the exact file layout:

- **Game engine code** — Phaser scenes, entity rendering, dungeon generation, tilemap drawing, combat logic. Everything that runs inside the Phaser game loop.
- **Game state** — The `GameState` class with its event system (see section 7 for the event contract). All game state accessible via a single import.
- **React UI** — All HUD overlays, side panels, dialogs, and screens. Reads from GameState via subscriptions, renders DOM.
- **Integration** — Arche API client, seed script, config file, shared types.
- **Infrastructure** — Docker Compose, Vite config, font assets.

### API Integration (Arche Client)

```typescript
interface GenerateRequest {
  archetype: string;
  constraints?: Record<string, any>;
  affixes?: {
    min_prefixes?: number;
    max_prefixes?: number;
    min_suffixes?: number;
    max_suffixes?: number;
  };
  seed?: number;
  count?: number;
}

interface GenerateResponse {
  things: GeneratedThing[];
  seed: number;
}

async function generate(request: GenerateRequest): Promise<GenerateResponse>;
```

**Usage examples:**

```typescript
// Creature spawn in a non-boss room (playerLevel=5, variance=2)
generate({
  constraints: {
    level: { gte: 3, lte: 7 },  // playerLevel ± creatureLevelVariance
    difficulty: { in: ["normal", "champion", "elite"] }
  }
});

// Creature spawn in boss room (playerLevel=5, variance=2)
generate({
  constraints: {
    level: { gte: 3, lte: 7 },
    difficulty: { in: ["boss"] }
  }
});

// Loot drop (no archetype, no rarity — Arche picks via blueprint weights)
generate({
  constraints: {
    level: { gte: 3, lte: 7 }   // creatureLevel ± itemLevelVariance
  }
});
```

The game calls `POST /api/generate` from the browser. Arche is configured with `CorsLayer::permissive()` for local dev. API key is embedded in the client config.

### Seed Script

TypeScript script (`scripts/seed.ts`) that generates Arche import JSON:

- Creates global meta attributes (enum types: rarity, difficulty, creature_subtype, etc.)
- Generates creature blueprints combinatorially (12 base types × 7 level bands × 4 difficulties)
- Generates item blueprints (weapons, armor, shields, accessories, potions, spells)
- Assigns affix pools to blueprints based on rarity/difficulty
- Outputs `blueprints.json`, `affixes.json`, `global-meta-attributes.json`

Run: `docker compose run --rm seed`

## 9. Game Configuration

All tweakable game mechanics are defined in a single **game config file** loaded at startup (file name and location decided by the implementing agent). This centralizes every numeric tuning knob so balance changes never require hunting through source code. The config is a plain TypeScript object that is:

- **Read once** during boot (before GameState is initialized)
- **Imported statically** — no runtime file fetch, no JSON parse, no config server
- **Type-checked** — the config type is shared across all game systems
- **Self-documenting** — each field carries a comment explaining what it tweaks

### Config Structure

```typescript
export const GAME_CONFIG = {
  /** Player base stats */
  player: {
    baseHp: 100,
    baseMp: 30,
    baseAttack: 10,
    baseDefense: 5,
    startingLevel: 1,
    maxLevel: 100,
  },

  /** XP required per level. Array indexed by level-1, last value repeats for all subsequent levels */
  xpThresholds: [
    10, 25, 45, 70, 100,  // levels 1→6
    140, 190, 250, 320, 400,  // levels 6→11
    500, 620, 760, 920, 1100,  // levels 11→16
    1300, 1520, 1760, 2020, 2300,  // levels 16→21
    // ... up to maxLevel; pattern: scaling curve
  ],

  /** Level-up resets XP to 0, next threshold is xpThresholds[newLevel] */
  leveling: {
    /** How much faster early levels are vs late (multiplier curve) */
    curveExponent: 1.5,
  },

  /** Level window for Arche generation requests (flat band, uniform selection) */
  generationWindow: {
    /** Creature/spawn level = playerLevel ± variance */
    creatureLevelVariance: 2,
    /** Item/loot level = playerLevel ± variance */
    itemLevelVariance: 2,
  },

  /** Post-victory recovery (% of max) */
  recovery: {
    hpPercent: 0.15,   // 15%
    mpPercent: 0.15,   // 15%
  },

  /** Combat damage formula coefficients */
  combat: {
    /** Extra random damage range applied to player attacks: rand(0, damageRollMax) */
    playerDamageRollMax: 2,
    /** Extra random damage range applied to creature attacks */
    creatureDamageRollMax: 2,
    /** Defense reduction on creature attacks (flat subtract) */
    creatureAttackPenalty: 2,
    /** Minimum damage per hit */
    minDamage: 1,
  },

  /** Creature spawn */
  creatureSpawn: {
    minPerRoom: 1,
    maxPerRoom: 4,
    /** Tile radius from entry door to exclude from spawn */
    entryExclusionRadius: 4,
    /**
     * NOTE: Difficulty distribution is NOT configured here.
     * Rarity/difficulty of spawned creatures is determined by Arche's
     * blueprint weights during generation. Tune weights in the seed script.
     * Non-boss rooms request difficulty in [normal, champion, elite].
     * Boss rooms request difficulty in [boss].
     */
  },

  /** Creature aggro ranges (tile radius, Chebyshev distance) */
  aggroRanges: {
    normal: 1,
    champion: 2,
    elite: 3,
    boss: 3,
  },

  /** Creature chase speed: 1 = same speed as player, 0.5 = half speed */
  creatureChaseSpeed: 0.5,

  /** Flee stun duration in milliseconds */
  fleeStunDuration: 1500,

  /** Loot drops: how many items drop per creature difficulty */
  lootDrops: {
    normal:  { min: 0, max: 1 },
    champion: { min: 1, max: 3 },
    elite:    { min: 3, max: 5 },
    boss:     { min: 5, max: 7 },
    /**
     * NOTE: Rarity distribution and item type are NOT configured here.
     * They are determined by Arche's blueprint weights during generation.
     * The level window for loot is controlled by generationWindow.itemLevelVariance.
     * Every item archetype (weapon, armor, potion, spell, etc.) is equally eligible.
     */
  },

  /** Inventory and spellbook */
  capacity: {
    inventorySlots: 18,
    spellbookSlots: 6,
  },

  /** Room tile dimensions */
  room: {
    width: 15,
    height: 11,
  },

  /** Dungeon generation */
  dungeon: {
    gridSize: 64,
    targetRoomRatio: 0.55,    // % of grid cells that become rooms
    extraEdgeRatio: 0.20,     // % of non-tree adjacencies added as loops
    transitionMs: 350,        // room fade duration
  },

  /** Movement */
  movement: {
    walkSpeed: 120,           // ms per tile
```

### How Config Is Used

```typescript
import { GAME_CONFIG } from './config';  // path determined by implementation

// In GameState initialization:
this.player.maxHp = GAME_CONFIG.player.baseHp;
this.player.baseAttack = GAME_CONFIG.player.baseAttack;

// In CombatSystem:
const damage = Math.max(GAME_CONFIG.combat.minDamage,
  playerAttack - creatureDefense + rand(0, GAME_CONFIG.combat.playerDamageRollMax)
);

// In CreatureSpawnSystem:
const variance = GAME_CONFIG.generationWindow.creatureLevelVariance;
const levelWindow = {
  gte: Math.max(1, playerLevel - variance),
  lte: Math.min(100, playerLevel + variance),
};

// In LootSystem (how many drops, not what drops):
const { min, max } = GAME_CONFIG.lootDrops[creature.difficulty];
const count = rand(min, max);
// Each drop calls Arche with level constraint only (no archetype/rarity filter)
```

### What Belongs in Config vs What Doesn't

**In config:** All numeric tuning values (HP thresholds, drop rates, timing, speeds, ranges, ratios). Anything marked "tweakable" in the PRD.

**NOT in config:** Structural code (scene names, UI layout, component tree, type definitions), visual design tokens (colors, fonts, spacing — those live in the design system/CSS), Arche API endpoints, Docker Compose settings.

### Adding/Changing Values

**Game config file** — for tuning game-side mechanics. No source file changes needed. For example:
- Make creatures faster: change `creatureChaseSpeed` to `0.75`
- Make leveling slower: adjust `xpThresholds` array or `curveExponent`
- Increase loot drops: bump `lootDrops.champion.max` from 3 to 5

**Seed script (Arche data)** — for tuning drop rates and content distribution. For example:
- Make potions drop more often: increase potion blueprint weights
- Make bosses rarer: decrease boss blueprint weights to `0.1`
- Shift item type balance: add more weapon blueprints to skew selection
- Adjust variance: change `levelVariance` in `SEED_CONFIG` (default 2)

This two-layer approach keeps Arche's weight system as the source of truth for content distribution, while the game config handles gameplay mechanics like movement speed, damage numbers, and drop counts.

## 11. Edge Cases & Error States

| State | Behavior |
|---|---|
| **Empty inventory** | All 18 slots show empty indicators. Tooltip does not appear. "Use Item" in combat shows "No usable items." |
| **Full inventory** | Cannot pick up new items from loot until space is freed. "Take" action on loot with full inventory results in "Inventory full" feedback. Player must drop/consume/equip items first. |
| **Full spellbook** | Replacement dialog when trying to add a spell from inventory or loot. Shows 6 current spells + new spell. Must select one to erase. |
| **Insufficient mana** | Spell is greyed out in combat spell panel. Tooltip or label shows "Not enough mana." Cannot select. |
| **No weapon equipped** | Attack stat = 10 (base). Attack action still available, damage formula works with base value. |
| **No armor equipped** | Defense stat = 5 (base). |
| **All equipment slots empty** | Player still functional with base stats. |
| **Attempt to equip mismatched slot** | Item cannot be dragged to wrong equipment slot. Drag target shows invalid (red) state. |
| **Drop last item** | Abandon confirmation dialog. If confirmed, item is destroyed. Cannot drop equipped items directly — must unequip first. |
| **Flee from combat** | Creature is stunned for 1.5s (no aggro, no movement). Player appears at entry door tile of the current room. |
| **Combat with 0 damage** | Damage formula floors at 1. Minimum 1 damage per hit. |
| **Boss defeated** | Victory screen. All creatures cleared. Player can continue exploring or quit. |
| **Player death** | Game over screen. Stats summary. Restart returns to title screen. |
| **Room with 0 spawns (edge case)** | If random roll yields 0, room is empty. Player passes through freely. |
| **Player cornered by creature** | Creature chases from nearest aggro'd position. Player must find escape path or engage. |
| **Chest in aggressive creature range** | Creature may aggro while player loots. Encounter triggers if creature touches player during loot. |
| **Multiple items of same type in loot** | Each is a separate entity (no stacking). Each must be picked up individually. |
| **Window resize** | Phaser game canvas resizes via `window.addEventListener('resize')`. Tile size recalculated. React re-renders responsive layout. |
| **Network error (Arche unavailable)** | Seed script must produce static fallback data for development. Production demo expects Docker Compose all running. |

## 12. Testing Strategy

### Unit Tests (Vitest)

Core game logic tested without Phaser or React:
- Combat math (damage formula, defense reduction, random variance)
- Inventory operations (add, remove, equip, unequip, swap, auto-equip)
- Spellbook operations (add, erase, slot limit, replacement)
- Player leveling (XP thresholds, level-up triggers)
- Loot generation (rarity distribution, drop count ranges)
- Creature behavior (aggro range calculation, chase logic, stun timer)
- Dungeon generation (connectivity, boss placement, grid size bounds)

### Integration Tests

- Seed script output validates against Arche import schema
- Arche `POST /api/generate` response parsing and Thing instantiation

### E2E Browser Tests (Playwright)

Required — not optional. Simulate human interaction:
- Game loads and renders the dungeon
- Player can move through rooms (WASD + click-to-navigate)
- Room transition (door) works with fade effect
- Creature encounter triggers combat UI
- Combat actions (attack, cast spell, use item, flee) produce correct outcomes
- Loot popup appears after victory
- Item pick-up and auto-equip works
- Inventory side panel opens, items can be dragged/swapped
- Spell can be added to/removed from spellbook
- Spell replacement dialog when full
- Boss kill shows victory screen
- Player death shows game over screen
- Mini-map toggle and zoom/pan work
- Responsive layout at mobile/tablet/desktop breakpoints
- Touch interactions (tap, long-press, swipe) function correctly

### Smoke Test

Docker Compose up → Arche healthy → game can generate a thing.
